# Dental support region work

**Current design change:** the teal broad-face overlay and generator are an older experimental policy, not the approved target for direct-print aligners. The new target is narrow contact bands beside validated contours on the non-fitting side; see [the contour-contact design](../docs/superpowers/specs/2026-10-25-dental-contour-contacts.md) and [implementation plan](../docs/superpowers/plans/2026-10-25-dental-contour-contacts.md). Do not interpret the current GLB's teal faces as approved tip locations.

Start with [the plain-language explanation](plain-language.md) to see what each colored part means. [The technical algorithm](technical-algorithm.md) gives enough detail to rebuild the detector in another language.

Double-click `run-review.bat` on Windows. Enter the path to an STL when prompted. The script uses the app's current orientation, dental placement, and support-build functions to create one GLB under ignored `dentalwork/output`, then selects it in File Explorer. The colors are blue for the two strong outer ridge chains, green for the weaker paths that join them, red for the central opening, teal for the **legacy broad face mask (not approved as a safe contact area)**, white for other faces, and gold for the actual app-generated support mesh. Open it in Blender or another glTF viewer and inspect all sides. The command reports proposed tips, omitted tips, and support-triangle count. No patient name is written into the GLB or output filename.

The GLB also has four *diagnostic* strips, each separately toggleable in Blender's object list: violet = outer contour's opening-facing side, amber = outer contour's other side, cyan = central opening's opening-facing side, magenta = central opening's other side. Each strip follows mesh-face adjacency in 3D from 0.2 to 1.2 mm away from its contour. Hide the gold supports and teal legacy mask to compare strips clearly. These colors show **both alternatives**, not a choice of the safe non-fitting side. The generator still uses the legacy teal mask until that side is anatomically verified and the placement policy is changed.

This is a local diagnostic, **not the new narrow contour-band implementation**. A generated GLB does not mean the proposed region, support contacts, or print pose is safe for dental use. If detection is inconclusive, the script writes no GLB. Files under `output` are ignored by Git because an STL or derived GLB may contain patient geometry. The one saved reference is the only aligner currently available for testing; tests on its rotations do not substitute for independent patient models.

The approved neutral [reference STL and screenshots](../docs/dental-reference/README.md) remain in `docs/dental-reference`. The application code remains in `src/core/analysis/dental.ts` and `src/core/analysis/dentalRegion.ts`.
