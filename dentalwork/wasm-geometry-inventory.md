# Geometry inventory

Status: shipped state at the end of unit U10. This is the U0 inventory of every production TypeScript file that did 3D or geometric work under `src/core`, `src/supports`, `src/editing`, `src/workers`, `src/components/viewport`, `src/state` and `scripts/dental-region-review`, kept with its plan labels and updated notes. Spec: [docs/SHIP-PLAN.md](../docs/SHIP-PLAN.md). Callers are production importers only (tests excluded), derived from the import graph at U0; "+N" means N more.

**The machine-readable truth today is `scripts/geometry-allowlist.json`**, used by the enforcing guard `scripts/geometry-guard.mjs` (run by `src/geometryGuard.test.ts`). It lists the 35 production files the guard flags, each `host-adapter` or `host-math` (5 of them, ratcheted with a reason). The table below is the U0 plan with notes brought up to date. The labels `port`, `port-into-shared-safety`, `frozen-reference` and `retire` are historical: no production TypeScript of those kinds remains. A row marked **Gone** names a file that no longer exists in the repository.

Labels (as planned at U0): **port** = rewrite in Rust; **port-into-shared-safety** = into the shared `supports/` safety engine (`supports/safety`, `supports/generate`), never a dental pipeline; **frozen-reference** = read-only reference, written once in Rust; **host-adapter** = TypeScript keeps it (UI, camera, files, settings, serialization, worker lifecycle); **retire** = deleted at cutover.

Row count: 113 (port 26, port-into-shared-safety 10, frozen-reference 7, host-adapter 65, retire 5). Of these, 39 files no longer exist (ported to Rust, merged, or deleted); the TypeScript oracle that once tested the ports (`scripts/test-support/ts-oracle/`) was deleted at U9 and its comparisons are recorded golden files in `scripts/fixtures/golden/`. Before U10 four host-adapter rows were added for `src/dental/{placement,legacyArea,diagnose}.ts` and `src/supports/exportGate.ts`.

## Import ABI notes

The mesh-session ABI throws stable `error.code` values (`INVALID_LENGTH`, `NON_FINITE`, `INVALID_INDEX`, `CAPACITY`, `INVALID_HANDLE`, and for STL `BAD_STL`, `NO_MESH`) in Node and the browser. `CAPACITY` is the over-capacity case; the host maps it to `over-capacity` with a message per job (import names the file).

- `center_positions_in_place` validates the whole XYZ array before it changes anything, computes original bounds and center, and returns nine numbers (center, min, max).
- `weld_positions_in_place` validates XYZ, indices and a finite 4 x 4 column-major matrix. It applies the matrix in f64, rounds each coordinate to f32 (rejecting overflow), welds by the same `mergeVertices(1e-4)` quantization with the JavaScript signed-32-bit wrap, and emits vertices in first-seen corner order. Empty indices mean sequential corners.
- `BinaryStlSession` takes each binary chunk once, skips the first 84 bytes across chunk boundaries, assembles split 50-byte records, reads three little-endian f32 vertices per facet, rotates STL Z-up to editor Y-up and feeds the shared first-seen welder. It never builds an unwelded whole-file triangle soup. The 18.7 MB reference matched the earlier TypeScript output bit for bit across uneven 1,000,003-byte chunks.
- `AsciiStlSession` scans completed newline blocks and keeps an unterminated tail between chunks, with the same rounding, rotation and welder. ASCII keywords are case-insensitive; non-ASCII whitespace is handled in Rust.
- A 24-file odd-STL corpus (colour-header binary, CRLF ASCII, non-ASCII whitespace, malformed files) in `scripts/fixtures/stl-corpus/` is checked against recorded goldens.
- `decimate_display` is display-only: it clusters in first-seen cell order, accumulates centroids in f64, discards degenerate triangles and returns typed arrays. Support and export meshes are untouched. It runs only for the heavy tier (over 1.5 million triangles). `python scripts/geometry_wasm_heavy_import.py` exercised that branch with a synthetic 1,506,848-triangle grid (one observation: 1,011.5 ms from worker message to result, 724,734 display triangles); it is a branch check, not a speed or memory-limit claim. A real heavy STL and a memory profile were not measured.
- `scripts/geometry_wasm_full_import.py` imports the reference through a real browser worker (373,956 triangles, 186,976 welded vertices; one run 260.2 ms). Not a performance guarantee.
- `node scripts/geometry-wasm-bench.mjs` bounds one bulk call (centering 187,000 vertices: JS 1.46 to 1.52 ms, WASM 1.18 to 1.24 ms median over five runs, Node). Do not extrapolate a user-visible speedup.
